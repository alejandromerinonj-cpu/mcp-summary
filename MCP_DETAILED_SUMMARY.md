## Technical details & notes

- SDK imports used (server):
  - `@modelcontextprotocol/sdk/server/mcp.js`
  - `@modelcontextprotocol/sdk/server/streamableHttp.js`

- SDK imports used (client scripts):
  - `@modelcontextprotocol/sdk/client/*` (StreamableHTTPClientTransport, Client, etc.)

- Streamable HTTP handshake requirements:
  - POST (initialize, call, etc.): must include Accept: `application/json, text/event-stream` and Content-Type: `application/json`. The POST body carries the JSON RPC payload.
  - GET (SSE connect): must include Accept: `text/event-stream` to receive Server-Sent Events.
  - The initialize() request MUST be performed once per stateful session; on success the server sets the `Mcp-Session-Id` header and maintains session state.

- Stateful vs Stateless transports:
  - Stateful: create an instance of StreamableHTTPServerTransport with a `sessionIdGenerator` and call server.connect(transport) once. The server issues `Mcp-Session-Id` and enforces single initialization per session (re-initialization triggers "Server already initialized").
  - Stateless: create a transport per request/interaction. No persistent session ID enforcement.

- SSE/resumability:
  - SDK supports event priming and an eventStore to allow resumable streams. Without eventStore/priming, reconnection behavior will be limited.
  - Client-side SSE AbortError often indicates the server closed the SSE stream after finishing a response. Client SDK includes reconnection/backoff logic.

- zod compatibility issue (Inspector):
  - Adding `@modelcontextprotocol/inspector` as a project dependency pulled in zod v3 (via an older dependency), conflicting with project zod v4. Mixed zod versions triggered runtime errors from zod-compat (e.g., `Cannot read properties of undefined (reading '_zod')`).
  - Workarounds:
    - Keep Inspector global (installed with `-g`) and run the UI/proxy from the global install.
    - If Inspector must be in-project, resolve via package manager overrides/dedupe/pinning (npm overrides, pnpm resolutions) so only a single compatible zod version is installed.

- Important implementation notes and gotchas:
  - Call `server.registerTool(...)` before `await server.connect(transport)`; otherwise tools will not be available when the transport is connected.
  - Express handlers must explicitly call `await transport.handleRequest(req, res, body)` (or appropriate call) — do not rely on auto-mounting.
  - Tool call payloads use the `arguments` property (not `args`).
  - Add a DELETE `/mcp` handler or equivalent to allow clients to terminate sessions (server-side cleanup) before re-initializing.
  - GET /mcp without Accept: `text/event-stream` → 406 Not Acceptable; ensure clients set correct Accept header.
  - Re-initializing a stateful session without closing it first → 400 Invalid Request: Server already initialized.


## Troubleshooting & lessons learned

- Peer dependency conflicts can block install; `--legacy-peer-deps` can be used for speed but consider resolving properly with overrides or switching package managers.
- Don’t add Inspector to the project until zod version conflicts are addressed — installing Inspector globally is an easy workaround.
- SSE AbortError is often expected for short-lived streams; if persistent streaming is required, enable eventStore + priming events for resumability.
- When debugging, watch server logs for Mcp-Session-Id issuance, initialize events, and transport error logs.
- The initialize/ping/call sequence needs to be done exactly once per stateful session. For repeated runs, either terminate the session or start a fresh server instance.
